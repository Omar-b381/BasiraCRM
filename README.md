# 📊 بصيرة CRM — نظام إدارة علاقات العملاء والفواتير والربط السحابي المتكامل

بصيرة CRM هو تطبيق سطح مكتب متكامل (Desktop App) مصمم خصيصاً للشركات وأصحاب المشاريع في العالم العربي. يجمع التطبيق بين قوة تطبيقات سطح المكتب وسهولة التزامن السحابي لتوفير إدارة مرنة لبيانات العملاء، إصدار وتصميم الفواتير الاحترافية، ومطابقة وتتبع شحنات التوصيل، بالإضافة إلى تكامل فريد مع قنوات التواصل ومزودي خدمة الواتساب (Meta / Twilio).

## 💡 نظرة عامة على المشروع
تم بناء بصيرة CRM ليعمل كتطبيق هجين مستند إلى بيئة **Electron** مع واجهة مستخدم مبنية بـ **React** و **TypeScript** وتصميم مخصص بـ **Tailwind CSS**. 

يتميز النظام بدعمه الكامل للعلامة التجارية البيضاء (White-Label)؛ حيث لا يشتمل التطبيق على روابط اتصال ثابتة لقواعد البيانات، بل يحتوي على شاشة تهيئة ترحيبية (Onboarding Wizard) تُمكن كل شركة من ربط خادمها السحابي الخاص على **Supabase** وحفظ مفاتيح الاتصال مشفرة محلياً، مع إمكانية إدارة هوية الفواتير بالكامل (الألوان، النصوص، والشعار المخصص المُرمز بصيغة Base64).

## 🛠️ المشكلة والحل

### المشكلة:
تواجه الشركات الناشئة ومتاجر التجارة الإلكترونية في الشرق الأوسط تحديات كبيرة في إدارة دورة حياة الطلبات والعملاء، ومن أبرزها:
1. **صعوبة مطابقة الشحنات**: استهلاك ساعات طويلة يومياً في مطابقة ملفات إكسيل الصادرة من شركات الشحن وتحديث حالات الفواتير يدوياً.
2. **عشوائية التواصل**: تشتت الموظفين بين منصات المراسلة وغياب الربط المباشر مع فواتير وبيانات العملاء.
3. **غياب الهوية الموحدة**: تعذر تخصيص مطبوعات الفواتير وشعاراتها بسهولة ومشاركتها عبر أجهزة الموظفين بالتزامن.
4. **التكلفة والاعتمادية**: معظم الحلول إما سحابية بالكامل وتتأثر بضعف الإنترنت، أو محلية وتفتقر لمزامنة البيانات بين الفروع والموظفين.

### الحل في بصيرة CRM:
* **تطبيق سطح مكتب بمزامنة سحابية**: يعمل محلياً بسرعة فائقة مع مزامنة فورية عبر قاعدة بيانات Supabase سحابية مؤمنة بنظام صلاحيات متقدم.
* **مطابقة فورية ذكية (Excel Matching)**: استيراد ملفات شركات الشحن ومطابقتها وتحديث الحالات سحابياً بضغطة زر واحدة.
* **تخصيص كامل للطباعة**: لوحة تحكم لتعديل ألوان الفواتير، النصوص الترويجية، ورفع الشعار وحفظه سحابياً بصيغة Base64 ليظهر لدى جميع الأجهزة فوراً.
* **خادم Webhook مدمج**: استلام رسائل الواتساب وتوجيهها حياً لواجهة الدردشة في التطبيق لدعم العملاء اللحظي.

## ⚙️ التقنيات المستخدمة ولماذا (Tech Stack & Rationale)

* **Electron**: لبناء تطبيق سطح مكتب متعدد الأنظمة (Windows/macOS) يستفيد من قدرات نظام التشغيل المحلي وتكامل الملفات مثل تصدير واستيراد الإكسيل والتحكم بالنوافذ.
* **React & TypeScript**: لبناء واجهة مستخدم تفاعلية، مرنة، وشديدة الاستقرار مع حماية أنواع البيانات (Type Safety) أثناء التعامل مع الاستجابات السحابية المعقدة.
* **Supabase (PostgreSQL + RLS)**: لتقديم قاعدة بيانات سحابية لحظية متكاملة وسريعة مع تفعيل سياسات أمان متقدمة (Row Level Security) للتحكم بصلاحيات الموظفين والوصول الآمن للبيانات عبر مفاتيح الـ Anon.
* **Zustand**: لإدارة الحالة العامة للتطبيق (State Management) بخفة وسلاسة بدون تعقيدات Redux.
* **Express & Webhooks**: لتشغيل خادم ويب داخلي مدمج يستقبل إشعارات المراسلات (مثل Meta Cloud API) ويمررها لحظياً للتطبيق.
* **ExcelJS**: لتوليد ملفات إكسيل متوافقة تماماً مع أنظمة شركات الشحن ومعالجة عناوين العملاء ديناميكياً.

## 🗄️ بنية قاعدة البيانات السحابية (Database Architecture)
تعتمد البنية الأساسية على قاعدة بيانات سحابية متوافقة ومرنة، وتتكون من الجداول التالية:

* **`system_employees`**: لإدارة حسابات الموظفين وصلاحياتهم (مدير، موظف مبيعات، موظف خدمة عملاء).
* **`customers`**: سجل جهات الاتصال ودليل الهاتف متضمناً معالجة وتجزئة العناوين والمحافظات.
* **`invoices`**: لإدارة الفواتير والطلبات، وربطها بشركات الشحن وأرقام التتبع وقيم التكلفة.
* **`invoice_items`**: لتفاصيل المنتجات والكميات المباعة والأسعار داخل كل فاتورة.
* **`whatsapp_providers`**: لإعدادات وقنوات الربط الخاصة بمزودي خدمة الواتساب.
* **`print_settings`**: لتخزين هوية الطباعة الموحدة للشركة (الألوان، الشعار المرمز، العنوان، الرقم الضريبي، وشروط الفاتورة).

> [!NOTE]
> جميع الجداول محمية بسياسات **Row Level Security (RLS)** لضمان أمن البيانات وعدم تداخل الصلاحيات.

## 🚀 دليل التشغيل والتثبيت محلياً (Getting Started)

### المتطلبات الأساسية:
* تثبيت بيئة **Node.js** (الإصدار 18 أو أحدث).
* مدير الحزم **npm** أو **yarn**.
* حساب **Supabase** (لتهيئة قاعدة البيانات السحابية للمشروع).

### خطوات التثبيت والتشغيل:

1. **نسخ المستودع (Clone Repository):**
   ```bash
   git clone https://github.com/Omar-b381/BasiraCRM.git
   cd BasiraCRM
   ```

2. **تثبيت الاعتماديات والمكتبات:**
   ```bash
   npm install
   ```

3. **تهيئة قاعدة البيانات على Supabase:**
   * افتح حسابك في Supabase وأنشئ مشروعاً جديداً.
   * انتقل إلى **SQL Editor** داخل لوحة تحكم Supabase.
   * انسخ محتويات ملف الهيكلية [schema.sql](file:///d:/PROJECTSIMPORTANT/mwasemcrm/supabase/schema.sql) والصقها في المحرر ثم اضغط **Run** لتأسيس الجداول والسياسات الأمنية.

4. **تشغيل التطبيق في بيئة التطوير:**
   ```bash
   npm run dev
   ```
   *سيقوم التطبيق بالعمل فوراً وفتح نافذة سطح المكتب وتوجيهك إلى شاشة التهيئة (Onboarding).*

5. **خطوة التهيئة الأولى:**
   * أدخل رابط مشروع Supabase ومفتاح الـ Anon Key الخاص بمشروعك (تجدها في إعدادات API في Supabase).
   * سيقوم التطبيق بفحص الاتصال بالخادم وقراءة جداول النظام والتأكد من توافقها، ثم حفظها محلياً مشفرة ونقلك لصفحة تسجيل الدخول.

6. **تسجيل الدخول الافتراضي (لأول مرة بعد تشغيل الـ SQL):**
   * اسم المستخدم: `admin`
   * كلمة المرور: `admin123` *(يرجى تغييرها أو إضافة موظفين جدد من شاشة الإعدادات لاحقاً)*.

## 🧠 الدافع والتحديات البرمجية (Storytelling & Challenges)

### الدافع:
جاء الإلهام لبناء هذا المشروع من حاجة السوق العربي لحلول تخطيط الموارد (ERP) وإدارة علاقات العملاء (CRM) التي تدعم اللغة العربية والخصائص المحلية دعماً أصيلاً (مثل هيكلة عناوين الشحن بالمحافظات والمدن العربية، والربط بالواتساب الذي يعد وسيلة التواصل الأولى للعملاء في المنطقة).

### التحديات والحلول:

#### التحدي الأول: انهيار مكتبة Supabase عند استيرادها بقيم فارغة (Module Initialization Crash)
عند إزالة روابط السحابة الثابتة لجعل التطبيق قابلاً للتهيئة متعددة الشركات (White-Label)، واجهنا خطأ `supabaseUrl is required` عند التشغيل الأولي للتطبيق؛ لأن مكتبة `@supabase/supabase-js` تقوم بالتحقق من صحة الرابط فور استدعائها في الكود (Module Import Time) وقبل تشغيل الواجهة.
* **الحل**: قمنا بكتابة نظام وسيط (Proxy Wrapper) في ملف [supabase.ts](file:///d:/PROJECTSIMPORTANT/mwasemcrm/src/lib/supabase.ts) يغذي المكتبة برابط ومفتاح افتراضيين كقناع أولي (`https://placeholder.supabase.co`) لمنع الانهيار، مع استخدام Proxy لتوجيه طلبات قاعدة البيانات ديناميكياً وجلب العميل الفعال بمجرد تغذية الإعدادات الصحيحة من المستخدم وحفظها.

#### التحدي الثاني: تكرار كائنات الاتصال وتحذير GoTrueClient
مع حركة التنقل بين الصفحات وإعادة استدعاء دوال جلب الإعدادات، تكرر إنشاء كائن الاتصال بـ Supabase مما تسبب في تحذيرات تكرار مثيلات GoTrueClient في متصفح Electron وظهور بطء نسبي في معالجة الجلسات.
* **الحل**: قمنا ببناء آلية فحص ومقارنة ذكية للرابط والمفتاح النشطين؛ بحيث لا يتم استدعاء دالة `createClient` مجدداً إلا إذا قام المستخدم بتحديث حقول الاتصال فعلياً بقيم مختلفة عن المخزنة في الذاكرة الحالية.
